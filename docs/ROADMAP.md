# Roadmap

| Phase | Scope | Status |
|---|---|---|
| 0 | Repository foundation, docs, app shell, FastAPI, environment config, database and migrations, health checks | Complete and verified |
| 1 | Authentication, protected routes, patient profile, validation, persistence | Complete and verified |
| 2 | Private medical document vault, validation, preview, ownership, storage adapter | Implemented; local verification complete |
| 3 | OCR/extraction adapters, structured candidate facts, confidence, review and correction | Local OCR plus an offline rule-based extractor (diagnoses, allergies, medications, labs, dates, doctor, hospital) with per-item accept/reject/edit, wrong-patient warning, duplicate skipping and role enforcement; optional AI provider falls back to rules on failure. Live provider calls remain unverified until approved credentials are configured |
| 4 | Source-linked chronological timeline and verification states | Implemented with category/source/date/state filters, editing/deletion, candidate references, conflict groups, uncertainty notes, and retained source snapshots |
| 5 | Consent-controlled emergency QR with hashed token, expiry, revocation, access logs | Complete and automated-tested: consented fields, up to 1-year wallet links, token rotation (renew), revocation, printable wallet card, coarse-IP access history, bilingual high-contrast scan page, patient-confirmed document facts (prescriptions limited to 180 days) |
| 6 | Family profiles and explicit dependent authorization | Dependent profiles, existing-account sharing, role-based switching, document read/write permissions, archival with history retention, and QR/grant revocation implemented and tested; legal authority remains an attestation |
| 7 | Security hardening, multi-worker rate limiting, end-to-end tests, pilot preparation | Implemented with automated coverage for email verification/reset, session revocation, Redis-backed shared rate limits, ClamAV fail-closed upload scanning, encrypted document/OCR/candidate storage and key rotation, request/log/header hardening, PostgreSQL migrations, container definitions, CI, and deployment guidance. The current workstation has no Docker executable, so Compose interpolation and image builds remain unverified here. External security review, DPDP/legal review, operational backup/restore validation, and supervised-pilot approval remain open. |
| 8 | ABHA/ABDM adapter after official docs, credentials, authorization, and approvals | Status UI and disabled connector are tested; live integration is externally blocked. ABDM describes sandbox-based ABHA API integration in its [official integration challenge material](https://abdm.gov.in/hackathon) |
| 9 | Consent, privacy controls, AI opt-in, export, localization, offline access, accessibility | Consent records and withdrawal, configured-provider consent gate, confirmed-history FHIR R4-aligned export, English/Hindi UI language switch, encrypted opt-in offline emergency card, installable PWA shell, first-run checklist, and automated axe checks implemented. See limitations below. |

Local OCR, rule extraction, source-linked review, timeline filters/editing/deletion, emergency QR, expiry/revocation/renewal, field selection, access history, family document permissions, dependent archival, account export/deletion, consent and withdrawal, AI consent gating, FHIR export, and encryption rotation have automated coverage. The browser journey includes registration/login, email verification/reset, extraction review/confirmation, timeline, QR access/renewal/revocation, family switching, export, deletion, opt-in encrypted offline card, responsive layout checks, and axe scans. English/Hindi translation is partial: shared navigation, authentication, selected forms and page headings are translated; full Hindi coverage is not complete. Accessibility automation is an initial axe scan of selected screens, not a complete WCAG audit. Offline emergency access stores selected fields encrypted in browser IndexedDB; it is device-specific and does not support remote wipe. Live email delivery, external AI-provider behavior, PostgreSQL service execution, Docker images, and production Redis/ClamAV operations have not been verified against deployed services in this environment. ABDM credentials are not configured; live integration remains disabled pending sandbox onboarding, credentials, authorization, and verified API workflows. The user-provided dependent-authority checkbox is an attestation and does not establish legal authority. No regulatory compliance, clinical validation, or production readiness is claimed. Pilot operation still requires Docker/Compose validation, restore testing, external security review, and legal/privacy review.
