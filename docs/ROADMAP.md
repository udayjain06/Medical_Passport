# Roadmap

| Phase | Scope | Status |
|---|---|---|
| 0 | Repository foundation, docs, app shell, FastAPI, environment config, database and migrations, health checks | Complete and verified |
| 1 | Authentication, protected routes, patient profile, validation, persistence | Complete and verified |
| 2 | Private medical document vault, validation, preview, ownership, storage adapter | Implemented; local verification complete |
| 3 | OCR/extraction adapters, structured candidate facts, confidence, review and correction | Local OCR plus an offline rule-based extractor (diagnoses, allergies, medications, labs, dates, doctor, hospital) with per-item accept/reject/edit, wrong-patient warning, duplicate skipping and role enforcement; optional AI provider falls back to rules on failure. Live provider calls remain unverified until approved credentials are configured |
| 4 | Source-linked chronological timeline and verification states | Implemented with category/source/date/state filters, editing/deletion, candidate references, conflict groups, uncertainty notes, and retained source snapshots |
| 5 | Consent-controlled emergency QR with hashed token, expiry, revocation, access logs | Complete and automated-tested: consented fields, up to 1-year wallet links, token rotation (renew), revocation, printable wallet card, coarse-IP access history, bilingual high-contrast scan page, patient-confirmed document facts (prescriptions limited to 180 days) |
| 6 | Family profiles and explicit dependent authorization | Dependent profiles, existing-account sharing, role-based switching, document read/write permissions, archival with history retention, and QR/grant revocation implemented and tested; legal authority remains an attestation |
| 7 | Security hardening, multi-worker rate limiting, end-to-end tests, pilot preparation | In progress. Done: proxy-aware per-client rate limits, encrypted documents at rest, production config validation, account export and deletion. Open: email verification and password reset (needs delivery provider), shared rate-limit store (Redis), malware scanning of uploads, encrypted OCR text, external security review, DPDP legal review |
| 8 | ABHA/ABDM adapter after official docs, credentials, authorization, and approvals | Status UI and disabled connector are tested; live integration is externally blocked. ABDM describes sandbox-based ABHA API integration in its [official integration challenge material](https://abdm.gov.in/hackathon) |

Local OCR, rule extraction, source-linked review, timeline filters/editing/deletion, emergency QR, expiry/revocation/renewal, field selection, access history, family document permissions, dependent archival, account export/deletion, and encrypted blob storage have automated backend coverage. The browser journey covers registration/login, extraction review/confirmation, timeline, QR access/renewal/revocation, family switching, export, and deletion. Live AI-provider behavior remains unverified; local OCR and rules work without a provider. ABHA/ABDM is externally blocked pending official sandbox access, credentials, approvals, and verified API workflows. The user-provided dependent-authority checkbox is an attestation and does not establish legal authority. Production security controls remain incomplete.
